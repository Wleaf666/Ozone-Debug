Ozone机构调试台 · 桌面版
完整操作步骤、命令含义、配置方法及最小化恢复说明见同目录“操作手册.md”。

普通用户启动：直接双击 dist\v0.4.0\OzonePanel.exe。
这是单文件Windows x64图形程序，已包含Python运行时和PySide6/Qt Widgets。
不需要Python、不需要Shell、不需要start.cmd。第一次启动会解压运行资源到临时目录。
可把exe复制到其他可写目录使用；它内置当前机构的默认config.json。

界面：
按taste-skill的重设计和minimalist-ui指导，采用浅色扁平工作台，减少嵌套容器，用分隔线组织设备。
位置数字使用等宽字体，输入上方有标签，键盘焦点可见；未读取不伪装为零值。
左侧：升降、翻转、夹爪按钮和最近位置；变量与配置；变量快照。
右侧：大字号命令返回状态、完整可滚动说明、带时间戳的操作记录。
协议命令与回复单独在“协议详情”，不会淹没操作结果。
状态颜色区分等待/执行中、成功、失败。命令已接受不等于运动已经完成。

使用顺序：
1. 先用Ozone加载与目标固件匹配的ELF，连接目标，保持程序运行。
2. 点击连接诊断，默认127.0.0.1:19200。
3. 工具读取版本欢迎信息，探测表达式求值、Cortex-M4目标与RAM读取。
   未知版本不凭猜测放行，按接口能力判断；诊断失败时写入按钮保持禁用。
4. 确认目标运行中，打开“允许写入”，再逐项操作。
5. 参数先写，命令最后写；工具读取命令消费和固件result，不自动重发失败/超时动作。
6. 点击刷新状态观察busy、zeroed、result和位置。位置为快照，不是实时示波器。
   Stop、Disable、失联也会清busy，不能仅凭busy=false认定到位。
7. 夹爪写bool后触发gpioOutputflag。无气缸传感器，不能据此确认夹紧。

配置：
“变量与配置”支持expression、type、writable和连接参数。
类型：u32、i32、float、bool、u8。表达式支持变量、成员、数字数组下标。
保存为exe同目录的.local.json；不修改固件，重新连接生效。
exe同目录的config.json可覆盖内置默认配置，.local.json优先级更高。
配置页还可读取/写入自定义变量；通用写入不会检查设备动作顺序。
每次访问重新解析对象及成员地址，拒绝空指针与非STM32F407 RAM区域。
复位、固件更换后应重新诊断，始终保持ELF与板上程序匹配。

边界：
不自动启动/升级Ozone，不直接连接J-Link，不暂停、继续运行、复位或下载固件。
关闭面板或断开连接不等于停止机构。软件Stop是保持当前位置，不是硬件急停。
运行中目标内存访问不可用时报告错误，不用暂停/恢复绕过。
当前真实Ozone的19200端口拒绝连接；界面及exe验证通过，但未验证真实电机动作。

开发者重建：
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe build.py
产物为dist\v0.4.0\OzonePanel.exe。build.py使用PyInstaller并收集所需Qt动态库和平台插件。
源码启动：.venv\Scripts\python.exe app.py
Git管理源码和构建说明，忽略.venv、build、dist及个人配置。

UI来源与许可证：
新版使用PySide6/Qt Widgets双缓冲绘制，修复旧Tk/CustomTkinter版本恢复时黑块逐次补画。
保持taste-skill指导下的浅色扁平布局，Socket后端和固件控制接口不变。
Qt/PySide6使用LGPL开源许可，完整声明见THIRD_PARTY_LICENSES.txt，依赖版本见requirements.txt。
